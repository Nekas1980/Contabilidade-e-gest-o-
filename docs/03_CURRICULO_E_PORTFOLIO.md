## 7. Texto para portefólio GitHub

### Contexto

A solução inicial consistia num cartão digital simples com dois meios de contacto. O projeto foi reestruturado para responder às necessidades de utilização real por uma profissional da área de contabilidade.

### Problema

Era necessário melhorar simultaneamente:

- apresentação institucional;
- credibilidade;
- organização da informação;
- experiência em dispositivos móveis;
- facilidade de contacto;
- manutenção técnica.

### Solução

Foi desenvolvida uma página institucional estática e responsiva com:

- proposta de valor clara;
- catálogo de serviços;
- explicação do método de trabalho;
- FAQ;
- contacto por WhatsApp e e-mail;
- formulário sem base de dados própria;
- SEO básico;
- acessibilidade;
- documentação técnica.

### Decisão arquitetural

Foi escolhida uma arquitetura estática em HTML/CSS/JavaScript devido à dimensão do projeto e à ausência de requisitos que justificassem framework, backend ou base de dados.

Esta decisão reduz dependências, custos e superfície de manutenção.

## 8. Como explicar numa entrevista

### Pergunta: “Foi um projeto académico?”

Resposta recomendada:

> Começou como um cartão digital simples e evoluiu para um projeto com utilização real por uma profissional de contabilidade. Tratei a evolução como um pequeno projeto de produto: analisei requisitos, preservei a versão estável, criei uma branch, reorganizei a experiência, implementei a solução e documentei as decisões.

### Pergunta: “Qual foi a parte mais importante?”

> A principal decisão foi evitar complexidade desnecessária. Para este caso, HTML, CSS e JavaScript são suficientes. Consegui criar um site rápido e profissional sem introduzir uma stack que aumentasse manutenção sem benefício de negócio.

### Pergunta: “Onde está a segurança?”

> Uma das decisões de segurança foi a minimização de dados. Como o objetivo é iniciar contacto, não existe razão para o site guardar os dados do formulário. O browser apenas prepara uma mensagem e abre o WhatsApp.

### Pergunta: “O que faria se fossem necessários pedidos online armazenados?”

> Aí mudaria a arquitetura: backend, validação do lado do servidor, base de dados, controlo de acesso, registo de consentimentos quando aplicável, logs e gestão segura de segredos. Não colocaria essas responsabilidades diretamente no frontend.

## 10. Enquadramento para candidatura em Cibersegurança / Sistemas

Embora seja um projeto web, existem competências transferíveis relevantes:

- redução da superfície de ataque através de arquitetura simples;
- minimização de dados;
- ausência de segredos no frontend;
- cuidado com ligações externas;
- rastreabilidade por controlo de versões;
- separação entre versão estável e desenvolvimento;
- documentação de riscos e limitações.

No currículo de cibersegurança, o projeto deve ser apresentado como complemento, não como substituto de projetos de redes, sistemas, SOC ou segurança.

## 11. O que não deve afirmar

Não apresentar como implementado aquilo que ainda não existe, nomeadamente:

- backend seguro;
- autenticação;
- base de dados de clientes;
- CRM;
- pagamentos;
- analytics avançado;
- auditoria de segurança formal;
- certificação de conformidade RGPD;
- testes automatizados completos.

A credibilidade do portefólio aumenta quando as capacidades e limitações são descritas com precisão.
